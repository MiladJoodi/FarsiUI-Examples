# Persian UI Taste

## What this skill is for

When designing a Persian / Iranian web interface, do not think:

> "Take a normal SaaS UI and make it RTL."

Think:

> "How would a really good modern Persian product be designed from the beginning?"

The goal is to create UI that feels **native, modern, confident, tasteful and specifically designed for Persian users**.

The interface should feel like a real Iranian digital product, not an English template translated into Persian.

---

# 1. The Most Important Rule: Have Taste

Do not blindly follow popular UI trends.

Do not generate the same interface every time.

Avoid the typical AI-generated formula:

```text
Hero
+
3 cards
+
gradient
+
rounded corners
+
huge heading
+
glass effect
+
purple/blue accent
```

Or:

```text
Sidebar
+
Topbar
+
4 KPI cards
+
2 charts
+
table
```

These are not design decisions.

They are defaults.

For every project, make deliberate decisions about:

* Layout
* Density
* Typography
* Shapes
* Spacing
* Navigation
* Content hierarchy
* Color
* Borders
* Components
* Interaction

The result should have a recognizable visual personality.

---

# 2. Persian Design Is More Than RTL

RTL is only the starting point.

Persian changes how the interface should be designed.

Think about:

* Persian text rhythm
* Persian heading proportions
* Persian line lengths
* Persian numbers
* Persian dates
* Persian labels
* Persian forms
* Iranian financial patterns
* Persian mobile UX
* Mixed Persian/English content
* Cultural familiarity

Do not simply mirror an LTR interface.

---

# 3. Study Good Iranian Products

Use high-quality Iranian products as **design references**, not templates.

Examples:

* SMS.ir
* Saraf
* Snapp
* Digikala
* Torob
* Divar
* Tapsi
* Alibaba.ir

When looking at these products, study:

* How they structure information
* How they use Persian typography
* How dense the interface is
* How they present actions
* How they use color
* How they handle pricing
* How they structure forms
* How they handle mobile
* How they create trust
* How they create visual identity

Do NOT copy their layout.

Extract the design thinking.

---

# 4. Prefer Distinctive Layouts

Do not always use symmetrical grids.

Good Persian products can use:

* Asymmetric layouts
* Editorial compositions
* Dense information areas
* Large focused sections
* Split layouts
* Strong horizontal sections
* Compact toolbars
* Lists
* Tables
* Timeline layouts
* Floating action areas
* Large visual areas
* Text-heavy compositions

Choose the layout based on the product.

---

# 5. Stop Using Cards for Everything

Cards are useful, but overusing them makes every interface look identical.

Do not automatically put every section inside:

```text
┌──────────────────┐
│ Icon             │
│ Title            │
│ Description      │
└──────────────────┘
```

Sometimes the correct design is:

* A clean section
* A divider
* A list
* A table
* A large heading
* A simple row
* A toolbar
* A border
* A full-width block
* Nothing at all

Whitespace can create hierarchy without a card.

---

# 6. Persian Typography Should Lead the Design

Typography is not decoration.

Choose typography that looks genuinely good in Persian.

Avoid:

* Tiny Persian text
* Excessively bold headings
* Extremely tight line-height
* Too many font weights
* Huge English-style headings that look awkward in Persian
* Poor Persian/Latin mixing

Persian typography should feel:

**clean + comfortable + confident**

Do not make everything bold just because Persian text can visually become dense.

---

# 7. Buttons Should Feel Designed

Do not use the same generic button everywhere.

Avoid making every primary action:

> یک دکمه بزرگ آبی با گوشه‌های خیلی گرد

Button shape, size and hierarchy should match the product.

Possible styles:

* Compact
* Strong
* Minimal
* Text-based
* Outlined
* Dense
* Editorial
* Large CTA

Use the style intentionally.

Also write natural Persian actions.

Instead of generic:

> ادامه

prefer contextual actions:

> مشاهده گزارش
> افزودن محصول
> شروع پروژه
> تکمیل خرید
> ذخیره تغییرات
> دریافت کد
> مشاهده جزئیات

---

# 8. Shape Language Matters

Do not automatically use:

```text
border-radius: 16px
```

on everything.

Corners should have a visual language.

A financial product may feel:

* precise
* compact
* structured

A consumer product may feel:

* softer
* friendlier

An editorial product may feel:

* sharper
* quieter
* typography-driven

Choose the shape language based on the product.

---

# 9. Don't Make Everything Soft

Modern UI does NOT mean:

* huge radius
* huge shadows
* glass
* gradients
* floating cards

Sometimes the best UI is:

* white
* gray
* black
* thin borders
* subtle radius
* strong typography
* carefully controlled spacing

Simple does not mean boring.

---

# 10. Color Should Have a Reason

Do not start every design with:

> blue + purple gradient

Color should support the product.

Use accent color strategically.

Color can indicate:

* Action
* Status
* Financial state
* Category
* Importance
* Brand identity

Do not turn the whole interface into an accent-color playground.

---

# 11. Density Is a Design Decision

Persian products often work well with purposeful information density.

Do not create enormous empty spaces simply because modern SaaS websites often do.

At the same time, do not make everything cramped.

Choose:

* Compact
* Comfortable
* Spacious

based on the product.

For example:

A trading/financial interface may need higher density.

A marketing landing page may need more breathing room.

A messaging app needs a different density again.

---

# 12. Iranian Patterns When Relevant

When the product naturally requires Iranian patterns, use them.

Examples:

```text
۰۹۱۲۱۲۳۴۵۶۷
۶۰۳۷ ۹۹۷۵ ۱۲۳۴ ۵۶۷۸
IR...
۴۸۰٬۰۰۰ تومان
۱۴ مهر ۱۴۰۵
```

Relevant patterns include:

* Mobile numbers
* National ID
* Bank cards
* Sheba
* Toman
* Jalali dates
* Iranian addresses
* OTP
* Persian financial terminology

Do not force Iranian patterns into unrelated products.

---

# 13. Persian Microcopy

Text should sound like a real Persian product.

Avoid robotic translations.

Bad:

> عملیات با موفقیت انجام گردید.

Better:

> ذخیره شد.

Bad:

> آیا از انجام عملیات حذف اطمینان دارید؟

Better:

> این مورد حذف شود؟

Keep Persian UI copy:

* Short
* Natural
* Clear
* Human

The tone should match the product.

---

# 14. Persian + English

Real Persian products often contain English technical content.

Handle it intentionally.

Examples:

* Email
* URL
* Username
* Code
* API
* Product names
* Technical terms

Do not allow mixed-direction text to become visually broken.

Use LTR treatment where necessary.

Persian content remains RTL.

---

# 15. Don't Make Every Product Look Like FarsiUI

This is especially important.

FarsiUI is a component library.

It should NOT force every product into one visual style.

Different products should look different.

Use the same components differently.

For example, the same Button can be:

* compact in a dashboard
* prominent in a checkout
* minimal in an editorial page
* strong in a landing page
* dense in an admin interface

The component is the primitive.

The composition is the design.

---

# 16. Avoid AI UI Clichés

Never add visual elements just because they look "AI generated".

Avoid:

* Random gradients
* Purple glow
* Neon blue
* Glass everywhere
* Floating blobs
* Sparkles
* Fake 3D objects
* Excessive shadows
* Excessive rounded containers
* Decorative icons everywhere
* Random abstract shapes
* Unnecessary animation

If an effect does not improve the product, remove it.

---

# 17. Be Creative Without Being Weird

Creativity should come from:

* Composition
* Typography
* Information hierarchy
* Layout
* Interaction
* Density
* Visual rhythm
* Product-specific details

Not from random decoration.

The design should make someone think:

> "این واقعاً خوب طراحی شده."

Not:

> "این رو AI ساخته."

---

# 18. Every New Project Needs a New Visual Idea

Before starting a new page, ask:

> What makes this interface different from the previous one?

Do not reuse the same:

* Hero
* Card layout
* Dashboard structure
* Header
* Sidebar
* CTA
* Section pattern
* Empty state

unless the product genuinely needs it.

Reuse good patterns when appropriate.

Do not reuse them because they are convenient.

---

# 19. Design for the Persian User First

Before finalizing the UI, ask:

### Does this feel native in Persian?

### Does the typography feel right?

### Are the numbers correct?

### Are dates familiar?

### Are actions natural?

### Does the layout make sense in RTL?

### Does the mobile version still feel intentional?

### Does it look like a real product?

### Does it have its own identity?

### Could someone mistake this for a generic AI-generated SaaS template?

If yes, redesign it.

---

# 20. Final Rule

**Do not translate an interface into Persian.**

**Design the interface for Persian users.**

Take inspiration from the best Persian products.

Understand their patterns.

Combine those ideas with modern product design.

Then create something new.

The goal is not:

> Persian version of a SaaS UI.

The goal is:

> **A genuinely good Persian product UI.**
